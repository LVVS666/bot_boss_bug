# Telegram Bug Bot

Бот собирает сообщения с тегом `#new_bug` из разрешённых тем Telegram-группы и
ведёт реестр в Google Sheets. Сообщение может быть с фотографией или без неё.

В таблице видны пять колонок:

1. `Ссылка на сообщение` — переход к исходному сообщению в Telegram.
2. `Фотография` — изображение из сообщения; без фото ячейка остаётся пустой.
3. `Описание бага`.
4. `Подтверждение исправления` — разработчик ставит чекбокс, после чего бот
   отправляет баг в заданный чат или тему тестировщиков.
5. `Исправлено` — тестировщик ставит чекбокс, после чего строка удаляется.

Служебные колонки справа скрыты. Они нужны для защиты от дублей, стабильного
номера бага и однократной отправки уведомления.

## Формат сообщения

В теме `Bugs` или `Development` отправьте текст либо фотографию с подписью:

```text
Через кнопку Create Signal появляется ошибка.
Обычная публикация работает.

#new_bug
```

## Настройка

Требуется Python 3.11 или новее.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Положите ключ сервисного аккаунта Google рядом с проектом под именем
`service-account.json`. Сервисному аккаунту нужны права редактора на таблицу, а
в Google Cloud должен быть включён Google Sheets API.

Основные переменные `.env`:

- `TELEGRAM_BOT_TOKEN` — токен из BotFather;
- `ALLOWED_CHAT_ID` — ID исходной группы;
- `ALLOWED_THREAD_IDS` — ID тем `Bugs` и `Development` через запятую;
- `GOOGLE_SPREADSHEET_ID` — ID таблицы;
- `GOOGLE_SHEET_NAME` — имя листа или пустая строка для первого листа;
- `FIX_NOTIFICATION_CHAT_ID` — ID чата, куда отправлять готовые к проверке баги;
- `FIX_NOTIFICATION_THREAD_ID` — ID темы внутри целевого чата, если нужна тема;
- `CLEANUP_INTERVAL_SECONDS` — период проверки чекбоксов, минимум 10 секунд.

Чтобы узнать ID группы и темы, запустите бота и отправьте `/where` в нужной
теме. В BotFather для бота должен быть отключён Privacy Mode.

## Вставка фотографий через Apps Script

Бот скачивает выбранный размер фотографии только в оперативную память, передаёт
его в Google Sheets и сразу освобождает память. Временный файл на диске не
создаётся. Для этого используется небольшой Apps Script из
`apps-script/Code.gs`:

1. В таблице откройте `Расширения` → `Apps Script`.
2. Замените содержимое `Code.gs` кодом из `apps-script/Code.gs`.
3. Откройте `Настройки проекта` → `Свойства скрипта`, создайте свойство
   `UPLOAD_SECRET` со случайной длинной строкой.
4. Нажмите `Развернуть` → `Новое развертывание` → `Веб-приложение`.
5. Выполнять от имени: `Я`. Доступ: `Все`.
6. Скопируйте URL развертывания в `IMAGE_UPLOAD_WEBHOOK_URL`, а ту же секретную
   строку — в `IMAGE_UPLOAD_SECRET`.

Apps Script принимает только запросы с секретом и вставляет изображение прямо в
ячейку строки. Максимальный размер передаваемого изображения — 2 МБ; бот
выбирает подходящий размер Telegram-фото.

## Запуск и проверка

```bash
python app.py
```

1. Отправьте тестовый `#new_bug` с фото и убедитесь, что появилась строка.
2. Установите `Подтверждение исправления` — в течение заданного интервала бот
   отправит уведомление в `FIX_NOTIFICATION_CHAT_ID`.
3. Установите `Исправлено` — строка будет удалена.

Если процесс был выключен, чекбоксы будут обработаны после следующего запуска.
Уведомление отмечается в скрытой колонке и повторно не отправляется.

## Docker и хостинг

```bash
docker build -t telegram-bug-bot .
docker run --env-file .env telegram-bug-bot
```

Для хостинга вместо файла можно передать ключ через
`GOOGLE_SERVICE_ACCOUNT_JSON` как исходный JSON или base64. `.env` и JSON-ключ
нельзя добавлять в Git.

Бот использует long polling, поэтому запускайте только один экземпляр процесса.
Подойдёт любой хостинг с постоянно работающим worker: Railway, Render Background
Worker, Fly.io, Cloud Run с постоянным экземпляром или VPS.
